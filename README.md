# نظام إدارة حلقات مسجد طه

مشروع Django لإدارة الحلقات القرآنية والدورات الإضافية والأساتذة، بحساب إداري واحد فقط.

## المميزات
- تسجيل دخول حصري لحساب إداري واحد (بدون تسجيل عام)
- **الحلقات**: عرض كل حلقة ككرت يتلوّن تلقائياً (🔴 أحمر = لم يكتمل تسجيل الحضور اليوم، 🟢 أخضر = اكتمل)، مع بحث فوري عن أي طالب بالاسم
- **تسجيل حضور تلقائي**: أربع حالات — حاضر / تأخر / إذن / غائب — تُحفظ فوراً بالضغط بدون زر حفظ، لكل طالب وللأستاذ المسؤول عن الحلقة
- **الدورات والدروس الإضافية**: دروس لفئة محددة من الطلاب (من أي حلقة)، بحضور مستقل تماماً عن الحلقة الأساسية، بنفس آلية الحلقة كاملة (تلوين، تنقّل، تصدير...)
- **الأساتذة**: صفحة موحّدة تعرض كل الأساتذة (المرتبطين بحلقة/دورة وغير المرتبطين)، مع إمكانية تسجيل "تفقد عام" لمن لم يُؤخذ له حضور اليوم
- **الغائبون**: صفحة تعرض الغائبين والمتأخرين والمسجَّلين إذن ليوم محدد، مع إمكانية تعديل حالة أي طالب مباشرة من نفس الصفحة، وعدد أيام غيابه آخر أسبوع/شهر
- **جرد تفصيلي**: صفحة ملف لكل طالب وكل أستاذ تعرض بياناته وسجل حضوره الكامل (مع صفحات Pagination)
- **تصدير CSV** يومي لحضور أي حلقة أو دورة أو لكل شيء دفعة واحدة
- **تكامل تلغرام**: إرسال نسخة احتياطية يومية لقاعدة البيانات، وسجل فوري لأي عملية حذف/تعديل من لوحة التحكم
- **الحضور السابق مباشرة**: بجانب كل طالب في صفحات الحلقة/الدورة/الغائبين شريط ملوّن لآخر 10 جلسات مع نسبة حضوره، بدون ضغط أي زر
- **روابط الأسماء**: الضغط على اسم أي طالب (في الحلقات، الدورات، الغائبين، الإحصائيات، السبر، البحث، لوحة التحكم) يفتح صفحة حضوره
- **الإحصائيات**: نسب مئوية بدل الأعداد، فترة «من تاريخ … إلى تاريخ» مع اختصارات سريعة، فرز الطلاب حسب نسبة الغياب/الحضور/الحلقة/العمر/الاسم، فلترة حسب العمر، مخططات SVG تعمل دون مكتبات خارجية، وتقرير PDF بنفس الفلاتر
- **تاريخ الميلاد** للطالب (يُحسب منه العمر تلقائياً)
- **السبر**: خانة لتفاصيل السبر والملاحظات مع إمكانية تعديلها
- **بحث محلي**: أسماء الطلاب تُخزَّن في المتصفح (localStorage) فيتم البحث فوراً دون طلبات للسيرفر، وتُحدَّث تلقائياً عند أي تغيير
- **استيراد Excel**: من ملف صادر مسبقاً عن النظام، بوضع «دمج» (إضافة الجديد فقط) أو «استبدال كامل»، مع تنزيل نسخة Excel مباشرة من صفحة المطور
- **حساب مشاهد**: يُنشأ من لوحة التحكم، ويرى الإحصائيات والسبر، ويستطيع إضافة السبر وتعديله
- **الصفحة الرئيسية**: متابعة اكتمال تسجيل الحضور اليومي لكل الحلقات والأساتذة + ملخص اليوم
- **قائمة «خيارات»** جانبية للهاتف، وتبويبات فرعية في لوحة التحكم وصفحة المطور، وصفحة «كيفية الاستخدام»
- **حضور آخر 4 أسابيع** بجانب كل طالب، كل أسبوع في إطار
- **الإحصائيات**: الفترة الافتراضية من أول تاريخ مسجّل حتى اليوم، تفصيل شهري + المتوسط والمجمل، إحصائيات السبر، فلترة وتقسيم صفحات، وخط «دبي» في PDF
- **ترحيل 0008**: ينشئ جدول سجل المساعد الإحصائي `AssistantQuery`
- **ترحيل 0007**: ينشئ جدول التسميع `Recitation` (نفّذ `python manage.py migrate`؛ يعمل تلقائياً في `build.sh` على Render)
- **ترحيل 0006**: يوحّد التواريخ المخزّنة بصيغة غير صحيحة في SQLite (مثل 2026-8-9) ليصبح الترتيب الزمني والفلترة صحيحين
- **تصدير صورة**: زر «📷 تصدير صورة» أعلى جدول «الحضور — آخر 4 أسابيع» في صفحة الطالب (وفي نافذة 📊 السريعة) يحفظ الجدول كصورة PNG بالاسم والحلقة والألوان، مع زر «📤 مشاركة» (واتساب…) على الأجهزة التي تدعم ذلك — يُرسم مباشرة في المتصفح بلا مكتبات خارجية
- **التسميع**: صفحة لتسجيل ما سمّعه كل طالب من القرآن الكريم، حلقةً حلقة (تنقّل سابق/تالي بين الحلقات + تاريخ): من (سورة، آية) إلى (سورة، آية) — وقد يمتد عبر عدة سور — مع النوع (حفظ جديد/مراجعة) والتقدير والملاحظات، والتحقق من عدد آيات كل سورة، وزر «تكملة من آخر مقطع» و«السورة كاملة»، وسجل لكل طالب يمكن تعديله وحذفه؛ ويظهر ملخصه في صفحة الطالب ويدخل في النسخة الاحتياطية والاستيراد (ورقة «التسميع»)
- **الإحصائيات حسب الأشهر**: في جدول الأفراد زر «📅 حسب الأشهر»: اسم الطالب - الحلقة - المتوسط الكامل ثم عمود لكل شهر ميلادي (فرز بأي شهر)، وأسفله متوسط الكل؛ ويظهر أيضاً في تقرير PDF وفي جدول الكادر
- **فرز الطلاب بالسحب والإفلات** (لوحة التحكم ← 🔀 فرز الطلاب): كل الحلقات حاويات كبيرة، تُنقل بطاقة الطالب من حلقة إلى أخرى بالماوس أو اللمس (الشاشة العرضية/الحاسب)، مع تراجع (Ctrl+Z) وبحث وتمرير تلقائي، ويُحفظ كل نقل فوراً
- **المساعد الإحصائي بالذكاء الاصطناعي** (الإحصائيات ← 🤖): اكتب سؤالك بجملة عادية فيتحوّل إلى جدول مع تصدير Excel وPDF. النموذج يحوّل السؤال إلى «مواصفة» منظّمة فقط (لا يكتب SQL ولا يرى بيانات الطلاب)، وتُنفَّذ المواصفة بمحرّك الإحصائيات نفسه فتتطابق الأرقام مع صفحة الإحصائيات؛ مع عرض «كيف فهمتُ سؤالك» ونموذج «تعديل التفسير» وسجل أسئلة. بدون مفتاح API يعمل «بناء يدوي» بنفس الجدول والتصدير
- **كاش الذاكرة**: تُحمَّل البيانات كثيرة القراءة (الحلقات وأعداد طلابها، فهرس الطلاب، الأساتذة، والإحصائيات الافتراضية) في ذاكرة التطبيق عند تشغيله، وتُبطَل تلقائياً عند أي تعديل (راجع «كاش الذاكرة» أدناه)
- تصميم متجاوب بالكامل (Mobile-first)، خط Dubai مضمّن فعلياً، الألوان مستوحاة من شعار المسجد

## التشغيل محلياً

```bash
# 1) أنشئ بيئة افتراضية (اختياري لكن يُنصح به)
python -m venv venv
source venv/bin/activate      # على ويندوز: venv\Scripts\activate

# 2) ثبّت المتطلبات
pip install -r requirements.txt

# 3) نفّذ الترحيلات (Migrations) - إلزامي هذه المرة (نماذج جديدة: Course, TeacherDailyAttendance...)
python manage.py makemigrations
python manage.py migrate

# 4) أنشئ الحساب الإداري الوحيد
python manage.py createsuperuser

# 5) شغّل الخادم
python manage.py runserver
```

ثم افتح المتصفح على: `http://127.0.0.1:8000/`

للوصول من جوالك على نفس الشبكة المحلية:
```bash
python manage.py runserver 0.0.0.0:8000
```
ثم من الجوال افتح `http://<عنوان-IP-الخاص-بجهازك>:8000/`

## إعداد بوت التلغرام

⚠️ **مهم جداً**: التوكن الذي أرسلته مكتوب داخل `masjid_taha/telegram_secrets.py` وهو ملف **مستثنى من git تلقائياً** (لن يُرفع أبداً إن استخدمت git). لا تشارك محتوى هذا الملف مع أحد. بما أن التوكن ظهر في محادثتنا نصياً، يُفضّل إعادة توليده من BotFather (أرسل له `/revoke`) إن كان هناك احتمال أن يطّلع عليه أحد غيرك.

**الخطوة الناقصة: تحديد وجهة الرسائل (`chat_id`)**
1. أرسل أي رسالة لبوتك على تلغرام (أو أضفه لمجموعة وأرسل فيها رسالة)
2. افتح في المتصفح: `https://api.telegram.org/bot<التوكن>/getUpdates`
3. ابحث عن `"chat":{"id": ...}` وانسخ الرقم
4. افتح `masjid_taha/telegram_secrets.py` وضع الرقم في `TELEGRAM_CHAT_ID`

**تجربة الإرسال يدوياً:**
```bash
python manage.py send_telegram_backup
```

**جدولة الإرسال اليومي التلقائي (لينكس - crontab):**
```bash
crontab -e
```
أضف سطراً (مثال: كل يوم الساعة 11 مساءً):
```
0 23 * * * cd /path/to/masjid_taha && /path/to/venv/bin/python manage.py send_telegram_backup >> /path/to/masjid_taha/telegram_backup.log 2>&1
```

**على ويندوز:** استخدم "جدولة المهام" (Task Scheduler) لتشغيل نفس الأمر يومياً:
```
"C:\path\to\venv\Scripts\python.exe" manage.py send_telegram_backup
```
مع تحديد "Start in" إلى مجلد المشروع.

**سجل عمليات لوحة التحكم**: أي حذف أو تعديل (حلقة/طالب/دورة/أستاذ) يُرسل تلقائياً كرسالة نصية لنفس المحادثة. لتعطيل هذا دون التأثير على النسخة الاحتياطية، غيّر `TELEGRAM_LOG_ADMIN_ACTIONS = False` في `settings.py`.

## ملاحظات أمنية قبل النشر الفعلي على الإنترنت
- غيّر `SECRET_KEY` في `settings.py`
- اجعل `DEBUG = False`
- حدد `ALLOWED_HOSTS` بدقة (اسم النطاق فقط)
- استخدم قاعدة بيانات إنتاجية (PostgreSQL مثلاً) بدلاً من SQLite إن كان الاستخدام كبيراً
- فعّل HTTPS
- لا ترفع `telegram_secrets.py` لأي مكان عام


## النشر على Render مع قاعدة بيانات Supabase

متغيرات البيئة في Render (Environment):

| المتغير | القيمة |
|---|---|
| `DATABASE_URL` | `postgresql://postgres.<project-ref>@aws-0-<region>.pooler.supabase.com:5432/postgres` (Session Pooler، بدون كلمة المرور وبدون تنصيص) |
| `DB_PASSWORD` | كلمة مرور قاعدة البيانات كما هي |
| `SECRET_KEY` · `ALLOWED_HOSTS` · `CSRF_TRUSTED_ORIGINS` | كما في `.env.example` |

- **Build Command:** `./build.sh` (يثبّت المكتبات، يجمع الملفات الثابتة، ينفّذ `migrate`، وينشئ جدول الكاش `createcachetable`)
- **Start Command:** `gunicorn masjid_taha.wsgi:application --workers 1 --threads 4 --timeout 120`
  (عملية واحدة وعدة خيوط: يناسب كاش الذاكرة أدناه ويوفّر RAM في الخطة المجانية)
- التخزين المؤقت الافتراضي (Django Cache) محفوظ في جدول `django_cache` داخل قاعدة البيانات.

### المساعد الإحصائي (ذكاء اصطناعي — اختياري)
- أضف في Render (Environment): `ANTHROPIC_API_KEY` (من console.anthropic.com). اختيارياً: `ANTHROPIC_MODEL` (الافتراضي `claude-haiku-5-5`) و`ASSISTANT_RATE_LIMIT_PER_HOUR` (الافتراضي 30 سؤالاً في الساعة لكل مستخدم).
- الاتصال بالخدمة عبر `requests` (لا مكتبات جديدة). يُرسَل نص السؤال وتاريخ اليوم وأسماء الحلقات فقط، ويعود JSON منظّم (أداة `build_query`) تُنظَّفه `validate_spec` بقوائم مسموحة قبل التنفيذ؛ لا يُنفَّذ أي نص من النموذج.
- الصفحة للحسابات الإدارية فقط (حساب «مشاهد» محجوب). **ترحيل 0008** ينشئ جدول `AssistantQuery` (سجل الأسئلة).
- التكلفة: استدعاء واحد صغير لكل سؤال؛ إعادة تشغيل استعلام من السجل أو «تعديل التفسير» مجاني.

### أمان الدخول
- كل صفحات التطبيق ونقاط نهايته محمية بـ `@login_required` (يتحقق منها `python manage.py test halaqat`، ملف `tests_security.py`).
- شاشة الدخول (`/`) لا تعرض أي تبويبات؛ ومن لديه جلسة سارية يُحوَّل منها مباشرة إلى الرئيسية بدل رؤية النموذج.
- صفحات النظام تُرسَل بـ `Cache-Control: no-store` فلا يعيد زر «رجوع» عرض صفحة بعد تسجيل الخروج، وتمسح شاشة الدخول فهرس الأسماء المخزَّن في المتصفح.
- الجلسة تبقى أسبوعين افتراضياً (إعداد Django). للأجهزة المشتركة: `SESSION_AGE_HOURS=12` و/أو `SESSION_EXPIRE_AT_BROWSER_CLOSE=true`. كوكيز الجلسة وCSRF مشفّرة (`Secure`) تلقائياً في الإنتاج.

### كاش الذاكرة (لتسريع الصفحات)
بُعد قاعدة البيانات (Supabase) يجعل كل استعلام يكلّف زمناً، فتُخزَّن البيانات كثيرة القراءة في ذاكرة التطبيق (`caches['memory']` في `settings.py`):

- **عند تشغيل التطبيق** (`wsgi.py`/`asgi.py`) يبدأ خيط خلفي يملأ الكاش مسبقاً بـ: قائمة الحلقات وأعداد طلابها، فهرس الطلاب، الأساتذة غير المرتبطين، وحساب الإحصائيات الافتراضي (الأثقل). لا يؤخّر إقلاع الخادم.
- **الإبطال تلقائي**: أي إضافة/تعديل/حذف (طالب، حلقة، أستاذ، دورة، حضور، سبر) يُبطل الكاش المتأثر فوراً (`halaqat/signals.py`) فلا تظهر بيانات قديمة. الاستيراد من Excel يُبطله كاملاً.
- الصفحات المستفيدة: الحلقات، الرئيسية، الأساتذة، لوحة التحكم، التنقّل بين الحلقات، البحث عن الطلاب، والإحصائيات (الحساب الثقيل يُخزَّن، والفرز/البحث/الصفحات تُطبَّق عليه فوراً).
- من «المطور ← ⚡ الكاش» ترى حالته وتمسحه وتعيد تحميله بزر واحد (مفيد بعد تعديل البيانات مباشرةً من Supabase).
- الكاش خاص بكل عملية (process)؛ لذلك يُنصح بعملية واحدة (`--workers 1`). مع عدة عمليات تبقى الصلاحية محدودة بـ 15 دقيقة كحدّ أقصى.
- لنقل البيانات الحالية من SQLite: نزّل نسخة Excel من «المطور ← تصدير Excel» محلياً، ثم استوردها على الموقع من «المطور ← استيراد Excel».
